# 1. Qué es el control de versiones y por qué se usa

Autor: Aylin Salazar

## 1.1 Definición

Un sistema de control de versiones que guarda los cambios de un proyecto, entonces así podemos es como podemos ver qué modificamos conforme vamos trabajando en un proyecto y luego también volver a una versión anterior si algo sale mal y ocupamos ese backup.

## 1.2 El método de las copias con fecha

Este método es, en resumidas cuentas, uan forma de copiar la carpeta del proyecto y ponerle la fecha para guardar cada versión. Algunos problemas que se puedendar a veces serían:
- Las copias ocupan mucho espacio.
- Podemos confundirnos sobre cuál es la última versión.
- Es difícil saber qué cambió entre las carpetas.

## 1.3 Qué resuelve un sistema de control de versiones
Lo principal que se resuelve con este tipo de sistema sería:
- Guarda el historial de cambios.
- Permite recuperar versiones anteriores.
- Facilita trabajar en equipo.
- Ayuda a saber quién hizo cada cambio.

## 1.4 Centralizado y distribuido

En un sistema centralizado, el historial está en un servidor principal. En uno distribuido, cada persona tiene una copia del historial y puede trabajar sin conectarse al servidor. Git es un sistema distribuido (ahorita por ejemplo estamos los 3 del grupo trabajando en conjunto en lugar de estar con solo una persona subiendo el code).
